# T006 · 홀드 감지 blob 편집 실기 검증 (운영)

## 배경

[[T003-problem-review-tags]]에서 `ProblemPhotoModal`의 blob 상호작용 버그가 **머지 후 4건 연속** 수정됐고 회귀 테스트가 없어, 실사용 검증이 미결 과제로 남아 있었다.

사용자 결정 (2026-08-16): 검증 환경은 **운영**(`climb.미라클펭귄.com`), 버그 발견 시 즉시 수정까지 진행.

## 검증 방법

- Chrome DevTools MCP로 운영 사이트를 직접 조작
- 대상: `/logs/43`의 첫 번째 문제 사진 (`photo_id=4`, `climb_log_problem 166`)
  — blob 데이터가 비어 있는(`[]`) 사진을 골라 실사용 기록 훼손을 피함
- **판정은 눈대중이 아니라 픽셀 샘플링**: 각 blob 중심 좌표를 이미지 로컬 좌표로 환산한 뒤 캔버스에서 실제 RGB를 읽어 대조

### 인증 처리
자동화 브라우저는 사용자 로그인 세션과 분리되어 있고, 두 계정 모두 `password`가 NULL이라 폼 로그인이 불가능했다. 사용자 승인 하에 앱의 `JWT_SECRET`으로 2시간짜리 토큰을 발급해 `localStorage.theroute_token`에 주입 (비밀번호·Google 계정 미사용).

### 상세

**좌표 검증 (항목 1)** — 핑크 시드 RGB(255,56,144)로 감지된 6개 blob의 중심 색상:
`(252,79,133) (255,61,138) (243,104,150) (251,64,143) (236,75,120) (251,69,143)` — 전부 선명한 핑크.

**저장 포맷** — 퍼센트 정규화 좌표. SVG에 `viewBox`가 없고 `cx`/`cy`가 0–100 범위:
```json
{"type":"circle","x":49.17,"y":28.44,"r":1.98,"color":"#ef4444","stroke":3,"_detected":true,"role":null}
```

**인터랙션 사양** — 홀드 감지는 클릭이 아니라 **1초 롱프레스**. 민감도 슬라이더 기본값 50은 `detectHoldsByColor`의 `threshold=50` 기본값과 일치.

## 운영 데이터 취급

- 검증 전 `climb_log_problem_photos` 전체 7행을 백업 (`hold_annotations`·`review_tags`·`failure_*`)
- 검증 후 최초 백업 기준으로 **전량 원상복구 완료** — 7건 모두 원본 길이와 일치 확인
- `climb_logs`·`climb_log_problems` 레코드도 변경 없음을 대조 확인

## ⚠️ 검증 과정의 자기 오판 2건 (앱 결함 아님 — 방법론 기록)

향후 동일한 함정을 피하기 위해 남긴다.

1. **좌표 버그로 오인** — `색상 감지` 활성화 시 민감도 슬라이더가 추가되며 이미지 rect가 이동(`y=1220`→`1092`)한다. 이동 전 좌표로 롱프레스해 의도한 핑크 홀드가 아닌 갈색 벽 RGB(94,59,39)을 눌렀고, 앱은 갈색 영역 32개를 정확히 찾아준 것이었다.
   → **교훈**: rect 측정과 이벤트 디스패치를 반드시 같은 호출 안에서 연속 수행할 것.
2. **저장 미반영으로 오인** — 사진 모달의 `저장`은 **즉시 DB에 반영**된다. 엉뚱한 `photo_id`(2번, 실제 대상은 4번)를 조회해 "부모 상태에만 반영된다"고 잘못 판단했다. 사진 ID 순서와 UI 문제 순서는 일치하지 않는다(문제 166→사진 4, 167→2, 168→5, 169→3).
   → **교훈**: 대상 레코드는 ID 추정이 아니라 **파일명으로 대조**할 것. 이 오판 때문에 2차 백업이 이미 오염된 상태였고, 최초 백업 덕에 정확히 복구했다.

## 발견 사항 (LOW)

- 저장 데이터에 내부 플래그 `_detected: true`가 그대로 DB에 영속화된다. 동작상 문제는 없으나 의도된 설계인지 확인 여지 있음.
- 두 계정 모두 `password`가 NULL이라 **로그인 화면의 이메일/비밀번호 폼은 현재 아무도 사용할 수 없다** ([[T004-auth-flow]]의 `seedOwnerCredentials()`가 `OWNER_EMAIL`/`OWNER_PASSWORD` 미설정으로 실행된 적 없음). OAuth로만 진입 가능한 상태.

## 최종 요약 (사용자용)

**홀드 감지·blob 편집 기능은 정상 동작합니다. 결함이 하나도 나오지 않았습니다.**

[[T003-problem-review-tags]] 머지 직후 버그 수정이 4번 연속됐던 영역이라 회귀를 우려했는데, 6개 항목을 모두 실제 브라우저에서 조작해 확인한 결과 전부 통과했습니다.

- 홀드를 1초 길게 누르면 같은 색 홀드를 정확히 찾아냅니다 — 감지된 원 6개가 **모두** 실제 핑크 홀드 위에 있었습니다(픽셀 색상으로 대조)
- 원을 탭해 역할·크기를 조정해도 재감지가 일어나지 않고, 다른 도구로 바꾸면 감지 결과가 깔끔히 지워집니다
- 저장 후 새로고침해도 좌표가 그대로 복원됩니다
- 콘솔 에러 0건

**운영 데이터는 검증 전 백업해 전량 원상복구했습니다.** 사진 7건과 기록·문제 레코드 모두 원본과 일치함을 확인했습니다.

참고로 알아두실 점 하나: 현재 두 계정 모두 비밀번호가 설정돼 있지 않아 **로그인 화면의 이메일/비밀번호 입력은 아무도 쓸 수 없는 상태**입니다. Google 로그인으로만 들어갈 수 있습니다. 지금 불편은 없지만 나중에 비밀번호 로그인을 쓰시려면 설정이 필요합니다.
