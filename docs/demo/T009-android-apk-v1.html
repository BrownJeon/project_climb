T009 안드로이드 앱 — 바뀌는 화면 데모 v1

수준 delta (규칙 DM-kw-risky-cta) · 기준 폭 390px · 라이트 테마 · 토큰 출처 web/src/styles/tokens.css · 앱은 운영 웹을 그대로 띄우는 껍데기이므로, 이번 작업에서 새로 보이는 것은 아래 4가지뿐이다. 기존 화면은 재설계하지 않는다.

기기 폭

먼저 알릴 사실 2건

  1. 요청서의 색 값과 실제 앱 색이 다르다. 요청서·designer.md·09-18 스펙이 근거로 삼은 web/src/styles/base.css(#fafafa·#ff5a3c·#1a1a1a·#6b7280)는 어디서도 import 되지 않는 파일이다(web/src/main.jsx 는 tokens.css·app.css 만 읽는다). 실제 화면 색은 tokens.css: 배경 --bg #f6f5f3, 카드·상단바·하단 탭 --surface #ffffff, 글자 --ink-1 #131313·--ink-3 #6b6b68, 주색 --primary oklch(67% 0.18 38)(sRGB 약 #ee6438). 데모 게이트 규칙(토큰 파일 = tokens.css)에 따라 이 데모는 tokens.css 값으로 그렸다. 이 차이 때문에 결정 D2·D3 이 생겼다.
  2. 아이콘 "홀드 3점" 과 생성기 원안이 다르다. 스펙 §11 은 "홀드 3점"이라 쓰지만 09-18 계획서의 생성기 상수 HOLDS 는 4점이다. 아래 A안이 계획서 그대로(4점), B안이 스펙 문구대로(3점)다.

연결 중

무엇이 잘못됐는지(제목) → 무엇을 하면 되는지(설명) → 행동(버튼) 순. 버튼 글자 19px 굵게 = 큰 글자 기준이라 3:1 로 충족. 네트워크가 돌아오면(online 이벤트) 누르지 않아도 자동으로 다시 연결한다.

동작 (승인 대상)

  1. "다시 시도" 를 누르거나 기기가 다시 온라인이 되면 → 실패 묶음을 숨기고 "다시 연결하는 중…" 을 보인 뒤 운영 주소로 이동(location.replace)만 한다. 플러그인·요청 없음.
  2. 이동이 또 실패하면 Capacitor 가 이 화면을 다시 띄우므로 자연히 "연결 실패" 상태로 돌아온다(별도 시간 제한 없음).
  3. 상태가 바뀔 때 화면 낭독기에 "다시 연결하는 중입니다" 를 알린다(aria-live="polite").

  • 실기기 관찰 항목(이번 범위 밖): 하단 탭은 원래 아래쪽 여백 28px(노란 점선)을 갖고 있다. 앱에서는 그 아래에 내비게이션 바가 한 번 더 붙어 탭 아래가 넓어 보일 수 있다. 스펙 §10 대로 웹 CSS 는 미리 고치지 않고, 실기기에서 보이면 웹 배포로 조정한다(재설치 불필요).

이 데모로 확인하지 못한 것

  • 실제 런처마다 다른 마스크 모양·크기, 테마 아이콘 색 — 실기기에서만 확인된다.
  • 시스템 바 높이·제스처 바 모양, 키보드 — 헤드리스로 재현되지 않는다(스펙 §13).
  • Custom Tab 의 실제 상단 표시줄 모양은 크롬 버전마다 다르다. 데모는 근사치다.
  • Pretendard 글꼴은 이 데모에 넣지 않았다(외부 글꼴 금지). 앱 화면은 Pretendard, app-shell·폴백 페이지는 시스템 글꼴이라 실제로도 다르다.
