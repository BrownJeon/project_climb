# 04. 암장 탐색 (목록)

> 경로: `/gyms` | 공통 규칙: [00-overview.md](./00-overview.md)

---

## 1. 목적·사용 흐름

**목적:** 다녀본/관심있는 클라이밍장을 검색·조회하고 상세로 진입.

**사용 흐름:**
1. BottomNav `🗺️ 기록` → `/gyms` 진입 (라벨만 "기록"으로 변경, 기능은 기존 암장 탐색 그대로)
2. 상단 검색 바에 암장 이름 일부 입력 → 결과 즉시 갱신 (디바운스 300ms)
3. (선택) "내 위치 기반" 토글 → 브라우저 geolocation으로 반경 5km 필터
4. 카드 클릭 → `/gyms/:id` 상세
5. 결과가 없을 때 "[+ 새 암장 등록]" CTA로 등록 가능 (선택 기능)

## 3. 사용 API

### 3.1 GET `/api/gyms`
**요청 query:**
| 파라미터 | 타입 | 비고 |
|---------|------|------|
| `q` | string | 이름 LIKE 검색 |
| `lat`, `lng` | number | 위치 |
| `radius` | number | km (기본 5) |
| `page`, `limit` | number | 페이지네이션 (기본 1, 20) |

**응답:**
```json
{
  "success": true,
  "data": {
    "total": 12,
    "page": 1,
    "gyms": [
      {
        "id": 2,
        "name": "더클라임 강남",
        "address": "서울 강남구 …",
        "lat": 37.4979,
        "lng": 127.0276,
        "phone": "02-…",
        "hours": "{\"mon\":\"10-24\", ...}",
        "price_info": "1일권 22000",
        "created_at": "..."
      }
    ]
  }
}
```

### 3.2 POST `/api/gyms` (선택 기능 — 새 암장 등록)
- 본 페이지 0건 결과 시 EmptyState CTA에서 사용
- 요청: `{ name, address, lat, lng, phone, hours, price_info }`

### 3.3 GET `/api/gyms?include_recent_routes=true` (카드별 최근 영상 미리보기)

암장 카드에 최근 영상 썸네일을 노출하기 위한 옵션 파라미터.

**백엔드 보강 필요:**
- `listGyms` 컨트롤러에 `include_recent_routes` 쿼리 처리 추가
- 각 gym에 대해 `ar_routes` LEFT JOIN으로 최근 3건의 `id`, `video_url`, `thumbnail_url`, `problem.color`, `problem.level`을 sub-select 또는 별도 batch 쿼리로 첨부
- 응답 추가 필드:
  ```json
  {
    "id": 2,
    "name": "더클라임 강남",
    "...": "...",
    "route_count": 12,
    "recent_routes": [
      { "id": 7, "thumbnail_url": null, "video_url": "...", "color": "yellow", "level": "V3" },
      ...
    ]
  }
  ```
- 미지정 시 기존 응답 형식 유지 (호환)
- 성능: gym 페이지당 N+1 방지 위해 단일 쿼리(SUBQUERY 또는 IN-clause) 권장

## 4. 컴포넌트 분해

```
<GymListPage>
  ├── <SearchBar value={q} onChange debounceMs={300} />
  ├── <LocationToggle active={useLocation} />     # ON 시 geolocation API 호출
  ├── <GymList>
  │     └── <GymCard gym onClick />*              # 02·05·07에서 재사용
  ├── <InfiniteScrollSentinel />
  └── <EmptyState>
        └── [+ 새 암장 등록]                       # → <NewGymModal>
```

**`<GymCard>` 표시 항목:**
- 이름, 주소, hours 요약(JSON parse 후 오늘 요일만), 거리(위치 기반일 때만)
- **최근 영상 미리보기**: 해당 암장의 최근 영상 썸네일 3개를 가로 스크롤로 노출 (있을 때만)
- 영상 수 뱃지: `🎬 {N}` (없으면 미표시)
- 썸네일 클릭 시 → `/routes/:id` 직접 이동 (카드 본체는 `/gyms/:id`로 이동)

## 5. 상태 / 데이터 모델

```ts
type GymListState = {
  q: string;                          // input value
  debouncedQ: string;                 // useDebounce(q, 300)
  useLocation: boolean;
  coords: { lat, lng } | null;        // geolocation 성공 시
  page: number;
  gyms: Gym[];
  total: number;
  loading: boolean;
};
```

- `debouncedQ` 또는 `coords` 변경 시 page=1로 리셋, 새로 fetch
- 위치 권한 거부 시: 토스트 + 토글 OFF로 자동 복귀

**거리 계산 (UI용):**
- 백엔드는 bbox 필터만 함 → 정확한 거리는 클라이언트에서 Haversine 계산
- 헬퍼: `utils/distance.js` (lat1/lng1/lat2/lng2 → km, 소수점 1자리)

## 6. 빈 상태 / 에러 / 로딩

| 상태 | 처리 |
|------|------|
| 첫 진입 (q="") | 가나다순 전체 1페이지 노출 |
| 첫 로딩 | 카드 5개 스켈레톤 |
| q 검색 중 | input 우측 spinner |
| 결과 0건 | EmptyState + 새 암장 등록 CTA |
| geolocation 거부 | 토스트 "위치 권한이 필요합니다" + 토글 OFF |
| API 실패 | 토스트 + 재시도 |

## 7. 추후 인증 도입 시 변경점

- 새 암장 등록은 인증 활성 시에만 노출 (현재는 `optionalAuth`로 통과)
- 본인 즐겨찾기 암장 표시 기능 추가 시: 별도 `gym_favorites` 테이블 + 별 표시

## 8. 수용 기준

- [ ] `/gyms` 진입 시 가나다순 암장 목록 노출
- [ ] 검색어 입력 → 300ms 후 결과 갱신
- [ ] 위치 토글 ON 시 권한 요청 후 거리 계산하여 카드에 표시
- [ ] 카드 본체 클릭 시 `/gyms/:id` 이동
- [ ] **카드의 최근 영상 썸네일 클릭 시 `/routes/:id` 직접 이동** (카드 클릭과 분리)
- [ ] 영상이 있는 암장은 `🎬 N` 뱃지가 카드에 표시됨
- [ ] 영상이 0건인 암장은 썸네일 영역 자체 미노출 (카드가 깨지지 않음)
- [ ] 스크롤 끝에서 다음 페이지 자동 로드
- [ ] 0건 시 새 암장 등록 CTA 노출, 클릭 시 모달
- [ ] hours JSON 파싱 실패해도 카드 깨지지 않음 (fallback "영업시간 정보 없음")
